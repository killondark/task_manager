## Purpose

Управление задачами через полный CRUD-цикл с жизненным циклом статусов, валидацией дедлайна и фильтрацией по статусу/приоритету.

## ADDED Requirements

### Requirement: Создание задачи
Система SHALL предоставлять форму создания задачи с обязательным заголовком и необязательными описанием, статусом, приоритетом и дедлайном.

#### Scenario: Успешное создание задачи
- **WHEN** пользователь отправляет форму с заголовком «Купить продукты»
- **THEN** создаётся задача со статусом `todo`, отображается сообщение об успехе, пользователь перенаправляется на страницу задачи

#### Scenario: Ошибка создания без заголовка
- **WHEN** пользователь отправляет форму с пустым заголовком
- **THEN** форма отображается снова с сообщением об ошибке валидации, задача не создаётся

#### Scenario: Ошибка создания с дедлайном в прошлом
- **WHEN** пользователь указывает дедлайн, равный вчерашней дате
- **THEN** форма отображается снова с ошибкой «дедлайн не может быть в прошлом», задача не создаётся

### Requirement: Просмотр списка задач
Система SHALL отображать список задач на странице index с возможностью фильтрации по статусу и приоритету.

#### Scenario: Отображение всех задач
- **WHEN** пользователь открывает страницу задач
- **THEN** отображается список всех задач с заголовком, статусом и приоритетом

#### Scenario: Фильтрация по статусу
- **WHEN** пользователь выбирает фильтр по статусу `in_progress`
- **THEN** отображаются только задачи со статусом `in_progress`

#### Scenario: Фильтрация по приоритету
- **WHEN** пользователь указывает фильтр по приоритету `5`
- **THEN** отображаются только задачи с приоритетом `5`

### Requirement: Просмотр задачи
Система SHALL отображать детальную информацию о задаче на отдельной странице.

#### Scenario: Открытие страницы задачи
- **WHEN** пользователь переходит на страницу задачи
- **THEN** отображаются заголовок, описание, статус, приоритет и дедлайн

### Requirement: Редактирование задачи
Система SHALL предоставлять форму редактирования задачи со всеми полями.

#### Scenario: Успешное редактирование
- **WHEN** пользователь изменяет заголовок и отправляет форму
- **THEN** задача обновляется, отображается сообщение об успехе

#### Scenario: Ошибка валидации при редактировании
- **WHEN** пользователь очищает обязательное поле заголовка и отправляет форму
- **THEN** форма отображается снова с ошибкой валидации, задача не обновляется

### Requirement: Удаление задачи
Система SHALL позволять удалять задачу с подтверждением.

#### Scenario: Успешное удаление
- **WHEN** пользователь подтверждает удаление задачи
- **THEN** задача удаляется, отображается сообщение об успехе, пользователь возвращается к списку

### Requirement: Статус задачи
Система SHALL поддерживать три статуса: `todo`, `in_progress`, `done` с значением по умолчанию `todo`.

#### Scenario: Задача создаётся со статусом todo
- **WHEN** создаётся новая задача без указания статуса
- **THEN** статус задачи равен `todo`

#### Scenario: Переход статуса
- **WHEN** пользователь изменяет статус задачи с `todo` на `in_progress`
- **THEN** статус задачи обновляется на `in_progress`

#### Scenario: Недопустимый статус
- **WHEN** задаче присваивается статус `invalid_status`
- **THEN** валидация не проходит, задача не сохраняется

### Requirement: Валидация дедлайна
Система SHALL отклонять дедлайн, который меньше текущего момента.

#### Scenario: Дедлайн в будущем
- **WHEN** пользователь указывает дедлайн через неделю
- **THEN** задача создаётся/обновляется успешно

#### Scenario: Дедлайн в прошлом
- **WHEN** пользователь указывает дедлайн на вчера
- **THEN** валидация не проходит, задача не сохраняется

### Requirement: Приоритет задачи
Система SHALL хранить приоритет как целое число, по умолчанию 0.

#### Scenario: Приоритет по умолчанию
- **WHEN** создаётся задача без указания приоритета
- **THEN** приоритет равен 0
