# task-interactors Specification

## Purpose

Слой интеракторов, инкапсулирующий бизнес-логику операций с задачами: создание, обновление и удаление. Интеракторы валидируют входные данные через dry-validation контракты и возвращают единообразный результат dry-monads (Success/Failure), который использующий их слой применяет для реакции.

## Requirements

### Requirement: Создание задачи через интерактор
Система SHALL создавать задачу через интерактор создания, принимающий объект задачи и валидные параметры, и возвращать в результате успех вместе с сохранённой задачей.

#### Scenario: Успешное создание
- **WHEN** интерактор создания получает задачу с валидными параметрами, например заголовком «Купить продукты»
- **THEN** задача сохраняется в БД и возвращается результат успеха, содержащий сохранённую задачу

#### Scenario: Ошибка валидации при создании
- **WHEN** интерактор создания получает задачу с невалидными параметрами, например пустым заголовком или дедлайном в прошлом
- **THEN** задача не сохраняется и возвращается результат ошибки, содержащий несохранённую задачу с ошибками валидации

### Requirement: Обновление задачи через интерактор
Система SHALL обновлять задачу через интерактор обновления, принимающий существующую задачу и параметры, и возвращать в результате успех вместе с обновлённой задачей либо ошибку валидации.

#### Scenario: Успешное обновление
- **WHEN** интерактор обновления получает существующую задачу и валидные параметры
- **THEN** задача обновляется в БД и возвращается результат успеха, содержащий обновлённую задачу

#### Scenario: Ошибка валидации при обновлении
- **WHEN** интерактор обновления получает существующую задачу и невалидные параметры, например пустой заголовок
- **THEN** задача не обновляется и возвращается результат ошибки, содержащий задачу с ошибками валидации

### Requirement: Удаление задачи через интерактор
Система SHALL удалять задачу через интерактор удаления, принимающий существующую задачу.

#### Scenario: Успешное удаление
- **WHEN** интерактор удаления получает существующую задачу
- **THEN** задача удаляется из БД и возвращается результат успеха, содержащий удалённую задачу

#### Scenario: Некорректный вход в интерактор удаления
- **WHEN** интерактор удаления получает значение, не являющееся задачей
- **THEN** возвращается результат ошибки и ничего не удаляется

### Requirement: Валидация входных данных интерактора
Система SHALL проверять входные данные интеракторов (объект задачи и параметры) контрактом до выполнения операции; при нарушении контракта возвращается результат ошибки с ошибками контракта, и операция с БД не выполняется.

#### Scenario: Невалидные параметры отклоняются контрактом
- **WHEN** интерактор создания или обновления получает параметры не в виде хэша или без объекта задачи
- **THEN** возвращается результат ошибки с сообщениями контракта, операция с БД не выполняется

#### Scenario: Пустые параметры отклоняются
- **WHEN** интерактор создания или обновления получает пустой хэш параметров
- **THEN** возвращается результат ошибки, операция с БД не выполняется

### Requirement: Единообразный результат интеракторов
Все операции над задачами через интеракторы SHALL возвращать единообразный результат, позволяющий вызывающему слою однозначно определить успех либо получить значение или ошибку.

#### Scenario: Различение успеха и ошибки
- **WHEN** вызывающий слой получает результат интерактора
- **THEN** он может определить, завершилась ли операция успехом или ошибкой, и получить либо задачу, либо ошибку
